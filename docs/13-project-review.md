# 项目分析与分批改进记录

分析日期：2026-11-14。基线提交：`1a8c39e`，版本：`0.5.0`。

本文记录项目架构、代码规范、性能、冗余与资源管理、功能完整性的审查结果，以及逐项修复的验证情况。
“已完成”表示实现及列出的本地检查通过，不代表未运行的平台或服务端集成测试已经通过。

## 基线与验证范围

- 核心为单头文件 `aino.hpp`，共 13,925 行；业务状态由应用持有。
- 包含 6 个顶层示例，SSH/SFTP 通过可选 libssh2 依赖接入，核心 UI 不依赖该库。
- Windows 本地使用 MinGW GCC 15.2，5 个非 SSH 示例 Release 构建通过。
- 17 个现有功能、交互及像素探针通过，共 3,018 项断言；文档编译检查与模糊台架运行通过。
- `macos_gallery_probe` 在此验证的是 Windows 后端上的画廊行为，不能证明原生 macOS 后端通过。
- 本地没有可用 Python 运行时，未通过 `tools/regress.py` 入口运行；SSH 联网、原生 Linux/macOS 未实测。
- 最小案例复现了多编译单元链接错误、输入框历史串用、主机记录句柄泄漏和光标停止调度。

## 一、项目架构

现有职责可以分为公开类型与 API、布局与交互状态、延迟浮层、CPU 光栅化、平台文字渲染和窗口后端。
立即模式 API、业务状态外置、可选网络依赖与核心分离的方向合理。主要问题在基础契约与测试边界。

### A01：多编译单元接入契约（P1）

README 要求仅一个编译单元定义 `AINO_IMPLEMENTATION`，但实现区的公开函数大量使用 `inline`。
当实现单元只包含头文件、另一个单元调用 `Ui` 时，构造、析构及帧函数出现未定义引用。
应由实现单元提供公开符号，并加入真正分离的实现与使用者构建检查。

### A02：资源对象所有权（P1）

`Ui` 与 `Window` 拥有裸 `Impl*` 并负责销毁，却允许编译器生成复制构造和复制赋值。
复制会共享同一资源，造成重复释放或赋值泄漏。应明确禁止复制；移动需要处理捕获对象地址的回调，不能默认启用。

### A03：跨线程唤醒（P1）

后台线程和 UI 线程共同读写普通 `bool need_frame/running`，缺少明确同步。
X11 的 `wake()` 还直接操作同一 Xlib 连接，公开跨线程承诺与内部线程前置条件不一致。
应使用可靠的线程间通知，并由 UI 线程消费请求，避免清标志时丢掉并发请求。

### A04：控件身份与会话隔离（P1）

控件身份主要由类型与坐标生成；位置变化会改变身份，不同业务数据在同一位置会共用历史。
最小案例中，在同一位置由数据 A 切到 B 后撤销，B 被恢复为 A 的内容。
应补充稳定控件 ID，并为 SSH 会话接入已有 `state_scope()`，仅在永久关闭时释放。
隐藏、切页和离屏必须保留状态，不能使用按帧淘汰绕开问题。

单头文件分发可以保留。内部模块化、库接入目标和测试入口可逐步完善；页面样式仍留在各示例 `.cpp`。

## 二、代码格式与工程规范

分区与类型命名较清晰，但引用空格、换行等风格存在差异，没有可执行的格式基线。
本地示例构建报告 `function_viewer.cpp` 中的未使用变量及续行注释告警。

### T01：日常测试门禁（P1）

现有 CI 仅在发布和手动触发时运行，日常提交和 PR 缺少自动门禁。
应增加触发条件，纳入接入契约与修复案例，并保证任一步编译失败会让任务失败。

### T02：格式与告警基线（P2）

增加 `.editorconfig`、`.clang-format`，优先约束新增和修改代码，避免全仓重排。
先消除明确告警，再逐步增加静态检查。重复的测试夹具可以在测试目录共用，示例页面样式不跨文件抽取。
工具脚本依赖与运行方式应可发现，CMake 应提供可选测试目标。

## 三、性能优化

已有按需重绘、悬停变化过滤、文字与折行缓存、字形预算、模糊降采样、绘图与画廊测量缓存。
本地光栅等价性 1,602 项通过，应继续保留像素等价检查。

### P01：有效性能基准（P1）

画廊 `AINO_BENCH` 分支在 `run()` 注册用户绘制回调前调用 `render()`，无法可靠测量完整画廊。
基准应复用正常绘制路径，并检查绘制次数。`perf_gallery.py` 的实窗采样属于另一条路径，需分别解释。

### F01：光标调度（P1）

输入框仅在光标可见阶段持续请求帧。按需调度最小案例约 37 帧、时钟到 0.633 秒后停止，焦点仍保留。
需要保证下一次闪烁仍会被调度，并减少不必要的连续整窗绘制；不能只强制整窗永久动画。

### P02：缓存与编辑历史预算（P2）

折行缓存逐次扫描寻找最旧项，单条超大内容可能超过名义预算；部分缓存达到上限后整体清空。
撤销条数有限，但保存完整字符串，大文本仍可能占用较多内存。
应明确字节预算、超大条目策略和测量方法，再决定是否采用更复杂的淘汰或增量编辑表示。

模糊台架在本机 `900×300 / blur=16` 约 2.14 ms/次，仅是局部计算观察。
优化优先级应根据用户回调、文字、阴影/模糊和上屏的有效采样决定；目前没有要求重写 GPU 后端的依据。

## 四、冗余与资源管理

### S01：主机记录文件句柄泄漏（P1）

`KnownHosts::verify()` 在已有记录匹配或不匹配时提前返回，没有关闭文件。
提取原始类实现的最小案例中，200 次匹配检查使进程句柄增加 200 个。
应使用 RAII 关闭所有分支，检查首次写入的错误，并测试已有记录与密钥变更路径。

### R01：冗余对象与日志资源（P2）

- Cocoa `cocoa_present()` 保存图像，`drawRect` 又重新创建图像，保存对象没有被消费；统一为单一路径。
- `frame_log_out` 缺少统一关闭管理，还需考虑两个诊断开关覆盖同一指针。
- `toolchain.py` 引用了仓库不存在的 `get_toolchain.py`，应更新失效说明。
- 清除编译器确认的无用变量与失效注释。

`tools/` 文件较多本身不构成冗余。应区分自动回归、性能台架、手动排障和历史复现，保留独有验证价值。
本地 `build/` 旧产物已被忽略，不应作为仓库生产代码删除依据。

## 五、功能完整性

### S02：私钥认证（P1）

`libssh2_userauth_publickey_fromfile_ex()` 当前把私钥路径放在 `publickey` 参数，`privatekey` 为 `nullptr`。
应修正参数，区分登录密码与私钥口令，并加入无需外部服务器的参数契约检查和可选本地服务器集成测试。

### S03：配置和凭据持久化（P2）

密码采用可逆混淆，界面已有明确说明。正式使用宜接入系统凭据存储。
配置以 `wb` 覆盖写，需改为临时文件和原子替换，失败应向调用方反馈。
上传使用 `fseek/ftell`，应补充 64 位定位及超过 2 GB 文件测试。

### F02：平台能力闭环（P2）

- Windows 有较多实际验证，仍需补齐通用键盘焦点遍历、按钮键盘激活与无障碍能力。
- X11 剪贴板仅声明所有权，读取为空；后台唤醒、IME/DPI 需要真实桌面验证。
- macOS 剪贴板为空实现，修饰键未写入；键盘、IME、HiDPI、调整尺寸和关闭事件需完善。
- macOS 空闲使用 2 ms 轮询，不能外推 Windows 阻塞空闲结果；素材子窗口线程模型也需适配。
- SFTP 目录传输、取消、超时与大文件支持边界应明确，并通过本地测试服务器验证。

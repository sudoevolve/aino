aino

一个头文件，用 C++ 构建熟悉的桌面界面。

  • 单头文件、C++17，核心零第三方 UI 依赖
  • CPU 光栅化，直接使用系统窗口、字体与绘图接口
  • 立即模式 API，业务状态由应用持有
  • 事件驱动，无事件、无动画时阻塞等待
  • macOS 风格、深浅主题与分组设置界面
  • 布局、表单、表格、图表、浮层与动画组件

Windows GDI · macOS Cocoa · Linux X11 / XWayland

获取与接入

下载 aino.hpp， 或克隆仓库查看完整示例。只在一个编译单元中定义 AINO_IMPLEMENTATION。

源代码 构建说明 Wiki 教程 许可协议 
git clone https://github.com/sudoevolve/aino.git
cd aino
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

核心使用系统开发库；可选 SSH 示例另需 libssh2。各平台链接参数见快速开始。

最小窗口

#define AINO_IMPLEMENTATION
#include "aino.hpp"

int main() {
    aino::Window win(880, 560, "Hello aino");
    if (!win.ok()) return 1;
    win.run([](aino::Ui& ui) {
        ui.heading("Hello, aino", {28, 28, 300, 40});
    });
}

常见问题

是否需要 GPU 或第三方 UI 框架？

核心通过 CPU 光栅化，并使用系统窗口、字体和绘图接口；不需要 GPU 图形 API 或第三方 UI 框架。Linux 的字体和图像功能使用系统运行库，可选 SSH 示例使用 libssh2。具体要求见构建说明。

为什么强调空闲时的 CPU 占用？

窗口在无事件时阻塞等待，后台状态变化后主动唤醒。光标闪烁、动画和持续播放仍需要更新，实际 CPU 开销随场景变化。缓存预算和采样方法见性能与资源。

Windows、macOS 和 Linux 的支持范围一样吗？

三个原生后端已存在，Linux 使用 X11 / XWayland。原生桌面互通、输入法、多显示器与无障碍能力仍有不同边界，请接入前查看平台能力矩阵。
